가상머신과 컨테이너

같은 프로젝트를 서로 다른 실행 환경에서 서비스하기

● Flask 웹 페이지 응답 확인

핵심 개념

01 · VIRTUAL MACHINE

가상머신 VM

하나의 컴퓨터 안에서 별도의 운영체제를 실행하는 가상 컴퓨터

  • VM마다 운영체제와 커널을 실행
  • 하이퍼바이저가 CPU·메모리 등을 할당

이번 실습: VirtualBox에 Ubuntu 설치

02 · CONTAINER

컨테이너 Container

호스트의 커널을 공유하면서 앱을 다른 앱과 격리하여 실행하는 환경

  • 컨테이너마다 전체 OS를 부팅하지 않음
  • 앱과 필요한 라이브러리를 함께 사용

다음 실습: 이 Flask 앱을 컨테이너에서 실행

03 · DOCKER

도커 Docker

앱의 실행 환경을 이미지로 만들고 컨테이너를 실행·관리하는 도구

  • 이미지: 앱 실행에 필요한 파일 묶음
  • 컨테이너: 이미지를 바탕으로 만든 실행 환경

실행 순서: Dockerfile → 이미지 → 컨테이너

VM과 컨테이너 비교

구분가상머신컨테이너
실행 단위운영체제가 설치된 가상 컴퓨터격리된 애플리케이션 프로세스
커널VM마다 별도로 실행실행 호스트의 커널 공유
시작과 자원OS 부팅과 자원 할당 필요일반적으로 시작이 빠르고 가벼움

컨테이너는 VM 안에서도 실행할 수 있습니다. Linux 컨테이너에는 Linux 커널이 필요합니다.

실습 연결

  1. 저장소 복제내 GitHub 저장소 → Ubuntu
  2. 실행 환경 구성Python·Flask 설치
  3. 서비스 확인앱 실행 → 브라우저 접속

Git clone은 파일과 변경 이력을 가져옵니다. 라이브러리 설치와 앱 실행은 별도 과정입니다.

박현규의 실습 기록: Ubuntu에서 프로젝트를 실행했습니다.
